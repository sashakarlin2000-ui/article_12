# Прогнозирование направления движения финансовых инструментов с помощью ансамбля LLM и поиска исторических аналогов
​
Пилотное исследование методов прогнозирования направления движения финансовых инструментов с использованием языковых моделей, рыночных режимов, поиска исторических аналогов и ансамблирования прогнозов.
​
Проект включает программный прототип, сохранённые результаты экспериментов и [сводку результатов статьи](article_results/README.md). Полученные результаты относятся к исследованному периоду и не являются инвестиционной рекомендацией.

## Идея исследования
​
Пайплайн объединяет несколько этапов:
​
1. Подготовка рыночных данных и признаков.
2. Определение рыночных режимов с помощью кластеризации.
3. Поиск исторически похожих ситуаций: без ограничения по режиму или в пределах текущего режима.
4. Получение прогнозов языковых моделей: `UP`, `DOWN` или `HOLD`.
5. Сравнение отдельных моделей и правил объединения их ответов.
6. Оценка классификационных метрик и двух сценариев торгового бэктеста.
​
В эксперименте сравниваются GPT-OSS 20B и 120B, Gemma 4 31B, Nemotron 3 Nano и Nemotron 3 Ultra. Двухмодельный ансамбль построен на ответах GPT-OSS 20B и 120B.
​
## Данные и эксперимент
​
- **Инструменты:** индекс S&P 500 (`SPX`) и акции AAPL, MSFT, NVDA, AMZN и TSLA.
- **Оценочное окно:** 60 торговых дат с 16 июля по 8 октября 2026 года; по 60 наблюдений на инструмент, всего 360 пар «инструмент — дата».
- **Цель:** `UP`, если следующее закрытие выше текущего; `DOWN` — если роста нет.
- **Метрики:** Accuracy, MCC, количество `HOLD`, точность активных прогнозов, накопленная доходность, Sharpe и максимальная просадка.
- **Сравнения:** обычный и режимно-зависимый retrieval, отдельные модели, ансамбль и три базовых метода.
​
При расчёте полной Accuracy прогноз `HOLD` считается ошибкой относительно бинарной цели. Точность активных прогнозов рассчитывается только на ответах `UP` и `DOWN`, поэтому эти показатели следует рассматривать вместе с покрытием сигналами.
​
## Гипотезы статьи
​
| Гипотеза | Проверяемое предположение | Результат на исследованной выборке |
|---|---|---|
| H1 | Режимно-зависимый retrieval повышает качество прогнозирования относительно обычного. | Убедительного подтверждения общего улучшения не получено: все пять интервалов разности Accuracy включают ноль. |
| H2 | Ансамбль улучшает качество прогнозов и/или торговые характеристики относительно отдельных компонентов. | Частичная поддержка по средним торговым показателям на данном окне; преимущество над обеими моделями по Accuracy не установлено. |
| H3 | Режимно-зависимые веса улучшают результат относительно фиксированных. | Предварительное ретроспективное сравнение на разделении 40/20 дат: 44,2% против 43,3% Accuracy на последних 20 датах. Устойчивое преимущество не установлено. |
| H4 | Confidence-weighted voting повышает полную Accuracy относительно majority voting. | На сохранённых ответах Accuracy выше на 10,83 п.п. при обычном и на 10,28 п.п. при режимном retrieval. |
| H5 | Confidence-weighted voting сокращает число прогнозов `HOLD` относительно majority voting. | На исследованной выборке число `HOLD` ниже в обоих вариантах поиска. |
​
## Основные результаты
​
| Сравнение | Результат |
|---|---|
| Режимная фильтрация | Направление изменения Accuracy зависит от модели; интервалы для пяти моделей включают ноль. |
| Confidence-weighted vs majority | Полная Accuracy выше на 10,83 п.п. при обычном и на 10,28 п.п. при режимном поиске; одновременно сокращается число `HOLD`. |
| Активные прогнозы ансамбля | Accuracy активных сигналов — около 50,2%; это само по себе не доказывает прогнозного преимущества. |
| Режимный GPT-OSS CW: условный вход по закрытию | Средняя накопленная доходность 9,70%, средний Sharpe 1,12, средняя максимальная просадка −10,51%. |
| Режимный GPT-OSS CW: вход на следующем открытии | Средняя накопленная доходность −6,61%, средний Sharpe −2,10, средняя максимальная просадка −14,17%. |
​
Торговые показатели усреднены по шести отдельно рассчитанным инструментам и не являются показателями единого портфеля. В базовой схеме сигнал и вход моделируются по одному и тому же закрытию, что может быть неисполнимо. Во второй схеме вход выполняется на следующем открытии, а выход — на закрытии той же сессии; средние доходности всех представленных систем отрицательны. Схемы отличаются одновременно временем входа, периодом удержания и структурой издержек, поэтому из них нельзя отдельно выделить влияние одного фактора.
​
Сравнение GPT-OSS с retrieval и без него выполнено через разных провайдеров: Ollama и OpenRouter. Поэтому оно не позволяет изолировать причинный эффект retrieval.

## Установка на Windows
​
В PowerShell из папки проекта:
​
```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```
​
Для просмотра параметров сквозного конвейера:
​
```powershell
python .\pipeline.py --help
```
​
Для проверки доступных тестов:
​
```powershell
python -m pytest
```
​
Запуск тестов и установка зависимостей не воспроизводят автоматически результаты статьи. Перед запуском реальных LLM ознакомьтесь с параметрами `run_real_experiment.py`, лимитами и условиями используемого провайдера. API-ключи храните локально в переменных окружения или `.env`; не добавляйте их в Git.
​
## Воспроизводимость и ограничения
​
Исследование ограничено одним оценочным окном. Воспроизводимость также зависит от подтверждения происхождения режимных меток, версий моделей и провайдеров и состава передаваемого моделям контекста. Для проверки устойчивости необходимы дополнительные независимые временные окна. `SPX` используется как ценовая прокси индекса, а не как напрямую торгуемый актив.
